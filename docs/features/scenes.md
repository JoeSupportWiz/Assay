# Scenes

**Entry:** `SceneLibraryView()` in the Scenes tab’s existing `NavigationStack`, inheriting `.environment(model)` for the app’s `AppModel`. For uninterrupted change detection after relaunch, also call `SceneLibraryStore.shared.attach(to: model)` from the root’s `onAppear`, before entering any appearance editor. No engine, entitlement, account or permission is required.

**Routes:** Scenes → New scene; Scenes → a saved scene (before/after review) → Activate scene, Edit scene, Share scene notes and colours, or Delete scene → confirmation. Activation returns to Scenes, where Undo activation is a single tap. There is no nested tab navigation stack; only the modal editor has its own stack.

**What changes:** Save records a named draft without applying anything. Activation writes `AppModel.wallpaperPalette` and `AppModel.themeID`; their existing setters persist the actual settings. Wallpaper match renders the palette in Assay. Other themes retain it for later. Palette options include presets and the current/saved palette, including custom swatches. Wallpaper, icon and widget notes are optional manual reminders: no system wallpaper or layout is read or changed. Sharing is an explicit plain-text export of the scene name, theme, palette values and notes, not an installable profile.

**Storage and undo:** This is a personal, initially empty library in this app installation’s local defaults, key `assay.scene-library.v1`. Display-name edits do not switch libraries; the app does not expose separate accounts. The library, selected UUID and one activation receipt are encoded together. Undo restores the exact prior theme and ordered colour array, restoring the prior selection only if that draft still exists with that appearance. A subsequent activation supersedes even a receipt with identical colours. Editing an active scene’s appearance or deleting its draft leaves the live settings untouched and unlinks the selection. Undo of its activation is still possible unless superseded. Unreadable saved data is not silently replaced.

The store compares the live pair on load/entry and immediately before an operation. Once attached, it observes writes to the two model properties even off-tab, invalidating selection and undo on outside changes (including changing away and back). Without the root attachment, changes made and reverted *before Scenes first opens on a new launch* cannot be detected. Separate AppModel defaults setters are not a crash-atomic transaction; a mismatched interrupted apply is not replayed automatically.

**Wallpaper export:** Open a saved scene and tap **Export wallpaper PNG**. Assay renders a portrait gradient from that scene’s colours at the screen’s native pixel dimensions and lets you save it in Files. Nothing is installed or set automatically.

**Checks:** From the repo root run `sh tests/scenes/smoke.sh` (Swift with Foundation and Observation). It compiles the production transitions and model adapter against synthetic UI-independent types using an isolated UserDefaults suite. For integration testing, save a Wallpaper match scene with a different palette and note; verify Save leaves live settings alone, review then Activate, relaunch, and tap Undo. Compare the original palette as well as the theme. Activate again, change the theme from More, then verify no undo is offered. Cancel a deletion before confirming it; neither path should change the live theme.
